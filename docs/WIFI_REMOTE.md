# NES local Wi-Fi receiver/controller

## Roles

- **Receiver APK**: installed on the emulator device. It starts/stops a listener, displays active IPv4 addresses and port, rotates the pairing code on each start, shows live connection state and a non-persistent accepted-input counter, and sends the current input state to the emulator's `NesController`.
- **Controller APK**: a standalone second-app entry point. It only offers receiver address/code fields and the eight NES buttons: Up, Down, Left, Right, A, B, Select, and Start.
- The receiver is intentionally in-process. Unlike WiFiPad's system-wide receiver, it doesn't create a generic Android virtual gamepad and doesn't require Shizuku/`uinput`.

## Protocol

- The host listens on TCP port 47531 on local IPv4 interfaces. Refresh the displayed address list if the device changes Wi-Fi network.
- Each receiver start generates a cryptographically secure 16-character code for that session.
- A challenge-response exchange authenticates the pairing with HMAC-SHA-256 and derives a session key.
- Input frames carry an 8-bit NES button mask, monotonically increasing sequence number, and HMAC. Duplicate/stale frames are ignored; JSON lines are limited to 1,024 bytes.
- A 200 ms authenticated heartbeat refreshes the receiver watchdog. The receiver releases all buttons on disconnect, input timeout, stop, or malformed/unauthenticated input.
- Only one remote controller can be paired at once. Pairing failures are capped per receiver session.
- IP addresses, input counts, pressed states, and connection status are held in memory only. No network traffic is logged or persisted. No telemetry, accounts, cloud services, or relay is used.

## Security boundary

The protocol authenticates the paired controller and protects message integrity, but TCP traffic is not encrypted. Use trusted local Wi-Fi only. Stop the receiver to invalidate the pairing code. The server binds local IPv4 interfaces, so do not leave it active on an untrusted network.

The Android manifest requests only `android.permission.INTERNET` for local TCP; any AndroidX dynamic-receiver permission is generated by the Android dependency at build time. No location or Wi-Fi scan permission is requested.

## Verification

Automated CI tests host/client pairing, simultaneous NES input, stale input validation helpers, and button release on disconnect using loopback sockets. CI builds and inspects both APK variants. **Two-physical-device Wi-Fi gameplay remains unverified**, and full NES gameplay is not available until PPU/APU/frame scheduling are implemented.
